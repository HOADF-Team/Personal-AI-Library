# Google Sheets и Apps Script: практические шаблоны

## Безопасный порядок

1. Прочитать названия листов, заголовки, формулы, локаль и связанные диапазоны.
2. Определить точный диапазон чтения/записи.
3. Перед массовым обновлением создать копию листа/файла или тестовый диапазон.
4. Не очищать лист и не переписывать формулы, пока не выяснено назначение существующих столбцов.
5. Считать данные из CSV, API, форм и пользовательского ввода недоверенными. Не смешивать их с формулами, которые генерирует скрипт.

## Пакетное чтение и запись

Плохо: обращаться к каждой ячейке внутри цикла через Spreadsheet service.

Лучше: один раз прочитать диапазон в массив, обработать его в памяти и записать результат одним setValues.

```javascript
function normalizeNames() {
  const sheet = SpreadsheetApp.getActive().getSheetByName('Data');
  if (!sheet) throw new Error('Лист Data не найден');

  const lastRow = sheet.getLastRow();
  if (lastRow < 2) return;

  const range = sheet.getRange(2, 1, lastRow - 1, 1);
  const values = range.getValues();

  const normalized = values.map(([value]) => [
    typeof value === 'string' ? value.trim() : value
  ]);

  range.setValues(normalized);
}
```

Этот пример изменяет только столбец A начиная со второй строки; имя листа и диапазон нужно адаптировать к реальной таблице. Если массив содержит недоверенные строки, начинающиеся с `=`, такой код небезопасен без предварительной обработки.

## Защита от внедрения формул

- Apps Script `Range.setValue()` и `Range.setValues()` трактуют строковое значение, начинающееся с `=`, как формулу. Поэтому импортированная ячейка с текстом вроде `=IMPORTXML(...)` может быть выполнена как формула, а не сохранена как исходный текст.
- Не передавать такие данные напрямую в `setValue(s)`. Для записи литерального текста используй подходящий безопасный способ: например, Google Sheets API с `valueInputOption: RAW` либо проверенное экранирование для конкретного метода. Не считать простую проверку/фильтр формул полноценной защитой, если данные должны сохраняться без изменений.
- Формулы задавать отдельным набором из доверенной логики через `setFormula(s)`; не конкатенировать пользовательский ввод в формулу.
- После записи перечитать тестовые ячейки и проверить, что текст остался текстом, а ожидаемые формулы находятся только в предусмотренных ячейках.

## Идемпотентность и триггеры

- Повторный запуск не должен создавать дубли. Используй стабильный ключ записи и проверку уже обработанных ID.
- Не создавать одинаковые триггеры при каждом запуске setup-функции.
- Для длительной обработки сохранять checkpoint и продолжать с последней обработанной строки.
- Обрабатывать LockService при конкурентном запуске.
- Не рассчитывать на бесконечное время выполнения: квоты и лимиты зависят от типа аккаунта и меняются.

## Формулы и локаль

Разделитель аргументов и формат дат зависят от локали. Не заменять запятые/точки с запятой механически во всём файле. Проверять формулу в целевой таблице и использовать правильный API для локали.

## Разрешения и секреты

При первом запуске Apps Script может запросить OAuth-разрешения. Объяснять пользователю, какие именно действия требуют доступа. Запрашивать минимально необходимые scopes и не использовать полный доступ к Drive/Sheets, если задачу покрывает более узкий scope. Секреты хранить в PropertiesService или отдельном защищённом хранилище, не в публичной таблице и не в коде репозитория.

## Перед сдачей

Проверить пустой лист, одну строку, несколько строк, дубликат, некорректный тип, повторный запуск и ошибку доступа. Для импортируемых значений дополнительно проверить строку, начинающуюся с `=`, и убедиться, что она записана как текст, а не как исполняемая формула. Не запускать массовую обработку реальной таблицы без разрешения.
