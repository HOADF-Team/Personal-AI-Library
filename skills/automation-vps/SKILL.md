# Automation and integrations

1. Сначала определи системы, направление обмена, формат данных, частоту и последствия сбоя.
2. Изучи официальную документацию API и зафиксируй актуальную версию, endpoint, auth, лимиты и ошибки.
3. Разделяй бизнес-логику, API-клиент, конфигурацию и хранение состояния.
4. Для запросов задавай timeout; повторы делай ограниченными и только для временных ошибок.
5. Обеспечь идемпотентность, чтобы повтор webhook/запроса не создавал дубли.
6. Проверяй подписи webhook, права доступа, схему входных данных и защиту от повторной доставки.
7. Секреты храни вне исходников и логов.
8. Учитывай rate limits, пагинацию, курсоры, временные зоны и изменение схем API.
9. Тестируй ошибки авторизации, timeout, 429/5xx, некорректный payload и повторное событие.
10. Перед развёртыванием оцени нагрузку, мониторинг, логи и восстановление после сбоя.

## Локальная методика
Используй [integration-runbook.md](references/integration-runbook.md) как базовый план. Конкретные API-контракты всегда сверяй с официальной документацией.

## Безопасность
Не запускать массовую синхронизацию, отправку сообщений, платежи или destructive API методы без явного подтверждения пользователя.
