# DevOps and VPS

1. До изменений выясни ОС, пользователя, рабочую директорию, способ запуска и состояние сервиса.
2. Сначала используй read-only диагностику: status, logs, process list, disk, memory и конфигурацию.
3. Не повторяй уже выполненные проверки без причины; учитывай полученные результаты.
4. Перед правкой конфигурации или данных делай резервную копию.
5. Не запускай массовое удаление, очистку БД, перезапуск критичных сервисов или смену firewall без согласования.
6. Для systemd проверяй unit, пользователя, рабочую директорию, переменные окружения и логи.
7. Для Docker учитывай volumes, networks, restart policy, лимиты ресурсов и доступность портов.
8. Не выводи секреты из env-файлов и логов в ответ.
9. После изменений проверяй конкретный сервис и его логи, а не только код возврата команды.
10. Учитывай ограниченные ресурсы VPS: RAM, swap, CPU, диск и сетевые лимиты.
