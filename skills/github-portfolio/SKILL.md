# GitHub portfolio

1. Оцени репозиторий глазами потенциального клиента или работодателя.
2. Помогай ясно показать назначение проекта, возможности, скриншоты, демонстрацию и инструкции запуска.
3. Пиши README с кратким описанием, функциями, установкой, использованием, ограничениями и лицензией.
4. Проверяй ссылки, названия, структуру и актуальность описания.
5. Для GitHub Pages учитывай ограничения статического хостинга и корректные пути ресурсов.
6. Не раскрывай секреты, приватные данные, внутренние адреса и ключи в публичных материалах.
7. Для постов о проекте готовь отдельный формат для GitHub, Telegram и X; не копируй один текст без адаптации.
8. Не приписывай проекту функции, которых нет в коде или подтверждённой демонстрации.
9. Перед публикацией изменений в репозитории показывай, какие файлы будут изменены, если действие может затронуть существующую работу.

## Локальная методика
Перед оформлением README, демо и релиза используй [repository-presentation-checklist.md](references/repository-presentation-checklist.md). Не приписывай проекту неподтверждённые функции.
