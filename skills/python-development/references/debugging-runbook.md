# Python: runbook диагностики и исправления

## Перед изменениями

- Найти точку входа и фактическую команду запуска.
- Проверить версию Python, venv, зависимости и рабочую директорию.
- Получить полный traceback, включая первую строку ошибки и цепочку вызовов.
- Зафиксировать исходное состояние git и затронутые файлы.
- Проверить, воспроизводится ли ошибка на чистом запуске.

## Разбор traceback

1. Читать traceback снизу вверх: последняя строка задаёт тип исключения и сообщение.
2. Найти первый кадр из кода проекта, а не только последнюю строку библиотеки.
3. Проверить значения и типы входных данных непосредственно перед ошибочной операцией.
4. Установить первопричину: неверный тип/значение, отсутствующий ресурс, несовместимая версия, неверный путь, гонка или сетевой сбой.
5. Не лечить симптом широким `try/except`, значением по умолчанию или отключением проверки.

## Минимальный цикл исправления

1. Сформулировать воспроизводимый сценарий.
2. Добавить тест или минимальный пример, который падает до исправления.
3. Внести минимальное изменение с сохранением публичного поведения.
4. Запустить точечный тест.
5. Запустить связанные тесты и статическую проверку.
6. Проверить diff: нет ли случайного форматирования, секретов, удаления логики и изменения конфигурации.
7. Сообщить, что реально запускалось, а что осталось непроверенным.

## Частые причины

| Симптом | Что проверить |
|---|---|
| `ModuleNotFoundError` | Активное окружение, имя пакета vs имя импорта, установка, cwd, sys.path |
| `ImportError` | Циклические импорты, несовместимая версия, конфликт имён файлов с пакетами |
| `FileNotFoundError` | Относительный путь от cwd, регистр имени, права, наличие файла |
| `TypeError` | Фактические типы и контракт функции, особенно None |
| `KeyError` | Схема входных данных, необязательные поля, изменения API |
| `AttributeError` | Тип объекта, версия зависимости, результат предыдущего вызова |
| Процесс зависает | Блокирующий I/O, timeout, deadlock, ожидание дочернего процесса |
| Работает вручную, но не как служба | Пользователь службы, cwd, PATH, venv, переменные окружения, права |

## Запреты по умолчанию

Не обновлять все зависимости разом; не удалять lock-файл; не менять схему БД; не перезаписывать пользовательские данные; не выводить секреты в лог. Каждое такое действие требует отдельного обоснования.
