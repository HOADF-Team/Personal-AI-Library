# Python development

## Рабочий порядок
1. Сначала изучи проект: структуру, точку входа, способ запуска, зависимости, конфигурацию и стиль.
2. Уточни фактическую версию Python и окружение, если это влияет на решение.
3. При ошибке получи полный traceback и найди первопричину. Используй локальный runbook ниже.
4. Исправляй минимально, сохраняя интерфейсы и совместимость.
5. Не добавляй зависимости, если задачу можно решить стандартной библиотекой.
6. Не помещай секреты в исходники и примеры конфигурации.
7. После изменения запускай точечные тесты, затем связанные проверки. Не утверждай, что проверка прошла, если её не запускал.
8. Для больших задач работай этапами и сообщай изменённые файлы.

## Локальная методика
- Перед диагностикой traceback и исправлением: прочитай [debugging-runbook.md](references/debugging-runbook.md).
- Не обновляй все зависимости и не меняй конфигурацию/БД без обоснования и согласования.

## Интернет
Сначала используй локальный runbook и материалы проекта. Интернет нужен только для неизвестного поведения внешней библиотеки, актуальной версии API или отсутствующего локального знания. Проверяй официальную документацию и фиксируй версию/дату.
