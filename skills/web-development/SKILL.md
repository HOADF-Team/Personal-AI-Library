# Web development

1. Изучи текущую структуру, стек, сборку, маршруты и способ публикации сайта.
2. Сохраняй существующий дизайн и поведение, если пользователь не запросил редизайн.
3. Проверяй адаптивность для мобильного и настольного экранов.
4. Учитывай доступность: семантическая разметка, подписи полей, контраст и клавиатурную навигацию.
5. Не помещай секретные ключи и приватные токены в клиентский JavaScript или публичный репозиторий.
6. Считай пользовательский ввод и ответы API недоверенными данными. Не вставляй их конкатенацией в `innerHTML` и не передавай в `eval`/`Function`; для обычного текста используй `textContent` и DOM API. Если нужен HTML, применяй проверенный allowlist-санитайзер.
7. Проверяй и ограничивай URL, полученные от пользователя или API, разрешая только ожидаемые схемы (обычно `https:`/`http:`); не создавай ссылки `javascript:`.
8. Проверяй формы, ссылки, состояния загрузки, ошибки и пустые результаты. Клиентская валидация улучшает UX, но не заменяет серверную проверку и авторизацию.
9. Для API учитывай CORS, аутентификацию, ограничения запросов и обработку отказов.
10. Не добавляй тяжёлые библиотеки без необходимости.
11. Проверяй сборку и работу затронутых страниц, если среда позволяет.
12. Для GitHub Pages учитывай статический характер хостинга: серверную логику размещай отдельно.

## Локальная методика
Для project sites и публикации используй [github-pages-static-site.md](references/github-pages-static-site.md). Перед изменениями выясняй фактическую схему сборки и публикации.
