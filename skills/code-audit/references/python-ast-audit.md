# Методика аудита Python через AST

## Назначение и границы

AST позволяет проверить синтаксис и структуру Python без исполнения исследуемого кода. Это не доказывает корректность runtime-поведения и не обнаруживает все динамические импорты, обращения через reflection или ошибки данных.

## Последовательность

1. Зафиксировать корень проекта, версию Python, точку входа и команду запуска.
2. Исключить виртуальные окружения, кэши, сборки и каталоги зависимостей.
3. Разобрать каждый `.py` через `ast.parse`. Синтаксические ошибки записать отдельно; остальные файлы продолжать проверять.
4. Собрать определения функций, классов, импортов и вызовов. Учитывать, что AST не разрешает динамические имена и не доказывает существование вызываемого метода.
5. Сверить абсолютные и относительные импорты с файловой структурой. Проверять namespace packages, `__init__.py`, sys.path, рабочую директорию и установленные внешние зависимости отдельно.
6. Найти подозрительные конструкции: bare `except`, `except Exception` без повторного raise/logging, `eval/exec`, запуск процессов, запись/удаление файлов. Это поводы для ручной проверки, не автоматический вердикт.
7. После статического анализа запустить только безопасные проверки в изолированном окружении: compileall, линтеры и тесты. Не запускать неизвестный entrypoint без оценки побочных эффектов.

## Интерпретация результатов

- **Подтверждено:** файл не парсится; импортируемый локальный модуль отсутствует при известной конфигурации запуска; тест воспроизводит ошибку.
- **Вероятно:** имя не найдено статическим поиском, но может создаваться динамически; импорт зависит от runtime path.
- **Не проверено:** внешняя зависимость, удалённый сервис, секрет, база или биржевой API недоступны.

## Что обязательно записать в отчёт

Для каждого дефекта: путь, строка, правило, фрагмент/доказательство, влияние, уровень серьёзности и статус. Не смешивать найденные ошибки с рекомендациями. После исправления повторять только затронутую проверку и связанные тесты.

## Безопасность

Не импортировать исследуемые модули ради introspection: импорт может выполнять произвольный код. AST-анализировать исходный текст. Не читать и не выводить значения секретов из .env; достаточно проверить наличие ключей конфигурации.
